# 2026-09-08 前后端检查记录

本轮从设置页保存按钮的异常黑底出发，检查共享前端控件、设置与变量恢复流程，以及剧情持久化、计时迁移和状态预算。确认的问题已在源码与编译产物中修复；检查结果不代表所有第三方角色卡或所有未覆盖组合均无缺陷。

## 修复的问题

| 问题 | 原因与处理 | 验证方式 |
| --- | --- | --- |
| 保存按钮周围出现黑色长条，下方内容可能被挡住 | 共享 SaveBar 使用聊天底色并默认 sticky。改为透明、随文档排布的保存行 | 真实宿主深色设置页，计算样式为 transparent / static，目视确认 |
| 相邻设置分区标题挤在保存行后 | 相邻 Section 没有外部间距。增加 28px 分区间距 | 真实设置页检查 |
| 缩窄窗口后当前页签藏在横向导航之外 | Tabs 没有跟随选中状态和容器尺寸显示当前项。仅调整导航横向位置，保留正文滚动 | 390px 视口复核 |
| 设置开关、数字和文本框缺少字段名称 | 可见标题没有关联实际控件。共享 SettingsRow / Field 向控件提供标签和说明 | React 控件测试、宿主可访问树 |
| 资产名与空选项冲突，禁用下拉仍可能接收旧选择 | 固定占位 ID 与有效资产值重合，回调不复核禁用状态。统一编码 ID、校验选项及禁用状态 | React 控件测试 |
| 切换语言时通信失败无法回退 | 只处理失败信封，没有处理 Promise 拒绝。统一回退本地语言、草稿与反馈 | 两类失败的设置测试 |
| 保存一个分区后其它未编辑设置变成待保存 | 基线接收最新服务器设置，但草稿只同步已保存区。现在同步所有未编辑字段并保留实际编辑内容 | 分区保存测试，包含其它区已有草稿的情况 |
| 旧变量备份恢复失败 | 旧备份使用 message/current 别名，宿主只接受当前历史中的数字下标。映射到所选消息并拒绝冲突别名 | 纯函数备份测试 |
| 接近大小上限的合法变量无法导出后再导入 | 校验把 version/scopes 封装算入变量预算。为封装保留少量独立预算，同时继续严格限制变量表为 1 MiB | 接近上限的导出导入往返测试 |
| 变量恢复可能在旧快照相等时直接提示成功 | 未重新读取服务器。相等分支改为只读复核，变化时保留备份并报冲突 | React + 模拟 remote 测试 |
| 损坏的旧世界书计时状态被清空或带入分支 | 解析异常被吞掉，复制没有校验。读取和复制均明确失败，保留来源文件 | 真实文件系统、模拟生成及分支准备测试 |
| 中文模板状态能超过声明的 4 MiB 上限 | 使用字符串长度替代 UTF-8 字节数。读取前检查文件大小，读后及写入前复核实际字节数 | 超限中文状态测试，校验原文件与 WAL 不变 |

## 检查范围

- 前端：角色、预设、世界书、用户、正则、记忆、设置七个主页面；设置的六个子页面；预设编辑区；共享保存行、下拉、标签、草稿保护与恢复确认。
- 布局：实际 Edge 宿主页面的桌面视口与 390 × 844 视口，检查可见排版、容器横向溢出、导航选中项和保存栏覆盖。
- 后端回归：完整测试集，包含剧情隔离、WAL 故障恢复、分支和楼层并发、提示词冻结、模板隔离、卡片业务桥、变量与消息状态、国际化与资产读写边界。
- 安装与产物：按 package-lock 在独立临时目录运行 npm ci；工作区重新构建、运行全量测试、执行 npm pack --dry-run，检查包白名单。独立安装避免更换正在运行的宿主所用 node_modules。

剧情写入、恢复及故障验证使用手写测试数据和临时文件系统，不调用真实模型。界面检查没有提交真实剧情变量恢复或保存导入资产。

- 桌面与 390 × 844 视口验证通过；窄屏选中页签完整可见，变量快照可读取，角色脚本编辑窗口没有横向溢出。

## 仍存在的第三方兼容边界

浏览器控制台仍可观察到某个角色卡外部状态栏直接读取 `parent.Mvu` 的 SecurityError。卡片运行在无同源权限的沙箱，无法直接读取主窗口对象；这与插件设置保存栏的黑底不是同一个原因。相关脚本需要使用沙箱内已有的 Mvu / 变量业务接口。本轮未修改用户导入的脚本资产，也没有通过增加 allow-same-origin 放宽权限。

经典 schema 和第三方正文状态栏的兼容范围仍以现有兼容文档为准。全量测试通过说明已覆盖场景没有回归，不能据此承诺任意外部脚本都能运行。
